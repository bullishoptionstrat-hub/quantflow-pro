# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Architecture

QuantFlow Pro is an options-flow terminal split into two independently deployed services plus Supabase:

```
Next.js 14 frontend (Vercel)  <-- REST + Socket.IO -->  Node/Express backend (Render)
                                                                    |
                                                              Supabase (Postgres + RLS)
```

- **`frontend/`** — Next.js 14 App Router, TypeScript, Zustand (`store/useStore.ts`) for client state, Socket.IO client (`lib/socket.ts`) for the live flow feed, Supabase SSR client for auth. Routes live under `app/` as one directory per feature (`flow`, `dark-pool`, `gex`, `heat-map`, `calculator`, `optimizer`, `power-alerts`, `watchlist`, `macro`, `news`, `settings`, `(auth)`). `middleware.ts` gates every non-auth, non-`/api` route behind a Supabase session, redirecting to `/login` when absent — or behind a demo cookie when demo mode is on (see the note below).
- **`backend/`** — Express + Socket.IO server (`src/server.ts`). `startIngestion(io)` (`src/ingestion/index.ts`) drives a pull/push pipeline from many market-data connectors (`src/ingestion/connectors/*` — Tradier, Polygon, Finnhub, plus 13 free-tier connectors: FlashAlpha, MarketData.app, Schwab, Tastytrade, TwelveData, FMP, CoinGecko, FRED, Reddit, NewsAPI, CBOE, Yahoo, Stooq). Every source normalizes to a `RawPrint` and funnels through `ingestPrint()` in `src/ingestion/flowEngineAdapter.ts`, which publishes the contract's NBBO, feeds the trade to the flow engine (`src/flow-engine/`), and maps finalized signals onto the wire shape. Signals are batched by `emitSignals` (100ms window) and broadcast as a **single global `flow_batch`**. REST routes under `src/routes/*` mirror the API reference below. When no live vendor keys are configured, ingestion falls back to an always-on simulation mode so the app still functions.
- **`backend/src/flow-engine/`** — the classification + scoring engine, vendored from `quantflow-modules/flow-engine` (the module is ESM; the backend is CJS, so it is copied rather than imported, with relative-import extensions stripped). It is byte-identical to the module apart from an added `resetDaily()`. **Change the engine here, and mirror it to the module** — or the module's test suite stops being a valid baseline for what ships.
- **`backend/src/enrichment/`** — the web-enrichment seam. `firecrawl/` is vendored from `quantflow-modules/firecrawl/src/services/firecrawl` (ESM module, CJS backend, so copied with relative-import extensions stripped — **change one, mirror it to the other**); `index.ts` is what the backend adds around it. Two rules live there and nowhere else: enrichment is **demand-driven, never scheduled** (its calls cost metered Firecrawl credits, so nothing fetches unless a request asks), and `AUTH` / `INSUFFICIENT_CREDITS` **latch the service off** until restart rather than retrying against a key that will not recover. Surfaced at `GET /api/sentiment/context`, `/context/status`, and `/regulatory/:slug`, and reported under `enrichment` in `/api/health`. With no `FIRECRAWL_API_KEY` it reports `disabled` and the rest of the app is unaffected.
- **`backend/src/provenance/`** — the data-rights registry. Every external dataset is classified per business mode and per capability (`DISPLAY` vs `PERSIST`), with the publisher's restriction quoted verbatim and the terms URL/read-date recorded. It **fails closed**: `UNVERIFIED` is refused (uncertainty resolves to refusal, not permission), an unregistered source is refused, and a malformed `BUSINESS_MODE` throws rather than degrading to either branch. `DISPLAY` and `PERSIST` are separate because the risk is separate — reading a delayed quote once is not the same act as accumulating a database out of it. `classify()` is the `PERSIST` decision; `mayOperateConnector()` is the `DISPLAY` one and gates whether a connector runs at all (see the note below).
- **`backend/src/persistence/`** — the durable signal history, and the reason the product can ever have a track record. `identity.ts` computes `decisionAt = max(lastEventAt, receivedAt, emittedAt)` (never `ts`, the first print — see below) and the content hash that is a signal's real identity; `recorder.ts` is the one path from a classified signal to storage and applies the rights gate; `grader.ts` grades M15/H1/D1 outcomes scheduled from `decisionAt`; `memoryStore.ts` is the reference implementation of the policy and `supabaseStore.ts` mirrors it. Store selection is reported in `/api/health` under `history` — a deployment that is silently discarding everything is the failure this module exists to make impossible to have by accident.
- **`supabase/`** — `schema.sql` (source of truth, run manually in the Supabase SQL editor) plus `migrations/` for incremental changes. `gate-proofs.sql` is re-runnable evidence that the signal-history constraints actually refuse what they claim to (`psql -d <db> -f supabase/gate-proofs.sql`; every `ERROR:` in its output is a pass). Tables are RLS-protected; `user_profiles` extends `auth.users`, and `api_keys.key_value` is a plaintext column intended to be encrypted via Supabase Vault in production (not yet wired up — treat as sensitive).
- **`quantflow-modules/`** — `flow-engine/` is the canonical home of the classification engine (sweep/block/split/multi-leg, NBBO side inference, deterministic unusualness scoring, outcome tracking) and holds the engine test suite plus the Polygon replay adapter for validating against real historical tape. It is **now integrated** into the backend via the vendored copy described above. `firecrawl/` is a web-enrichment module (FINRA doc sync, news context, research workflows) and is **now integrated** via a vendored copy at `backend/src/enrichment/firecrawl/` — same arrangement as the flow engine, and the same mirroring obligation. Check whether work belongs here vs. in `backend/src/ingestion` before duplicating logic.
- Root-level `qf-firecrawl (1).zip`, `qf-flow-engine.zip`, `quantflow.zip` are uploaded archives, not part of the working tree — the unpacked, current sources are `quantflow-modules/` and this repo itself.

## Commands

```bash
# Can this deployment accumulate a track record? (backend/tools/collection)
cd backend && npm run collection:doctor                       # config only
npm run collection:doctor -- --url http://localhost:3001      # plus live state

# Preview — the UI against a captured backend, in ~35MB (backend/tools/preview)
cd backend && DEMO_MODE=1 npm run dev                 # in another shell
npm run preview:capture -- --out .preview/cap         # record what it says
cd ../frontend && npm run build
cd ../backend && DEMO_MODE=1 npm run preview -- --cap .preview/cap --site ../frontend/.next

# Frontend
cd frontend && npm install
npm run dev      # http://localhost:3000
npm run build
npm run lint      # next lint
npm test          # vitest run — formatters, empty states, and the fetching pages
npm run verify    # tsc --noEmit && vitest run

# Backend
cd backend && npm install
npm run dev       # ts-node-dev, auto-restart, http://localhost:3001
npm run build      # tsc -> dist/
npm start          # node dist/server.js
npm test          # tsx --test test/*.test.ts — adapter/wire-mapping tests
npm run typecheck  # tsc --noEmit


# flow-engine module (canonical source; backend ships a vendored copy)
cd quantflow-modules/flow-engine && npm install
npm test        # tsx --test test/engine.test.ts test/outcome.test.ts
npm run typecheck
```

Environment setup: copy `.env.example` to `frontend/.env.local` and `backend/.env` respectively (see README's "Environment Variables Reference" for the full key list per service). The backend's authoritative key list is the root `render.yaml`, held to `src/` in both directions by `backend/test/renderBlueprint.test.ts` — a variable read by no code and a variable declared nowhere are both failures there. Run `supabase/schema.sql` in the Supabase SQL editor before first run (RLS-protected tables; the app expects them to exist).

Deployment: frontend → Vercel (root directory `frontend`, rewrites in `frontend/vercel.json` must point at the deployed backend URL); backend → Render via the root `render.yaml` Blueprint (`rootDir` is set there). Render's free tier sleeps services after 15 minutes of inactivity.

## Notes

- **Demo mode** is a read-only unauthenticated path, **off unless both `NEXT_PUBLIC_DEMO_MODE=1` (frontend) and `DEMO_MODE=1` (backend) are set**. Two independent conditions gate every step, so neither a stray cookie nor a stray header opens anything on its own: `/demo/enter` 404s, the `qf_demo` cookie is ignored by `middleware.ts`, the login button is not rendered, and `requireAuthOrDemo` 401s without `X-QuantFlow-Demo: 1`. **`/api/chain` and the three enrichment endpoints stay on plain `requireAuth`** — they return entitled vendor data or spend metered credits, and demo traffic must never reach them. When adding a route, put it on `requireAuthOrDemo` only if it costs nothing per call. The `DemoBanner` is deliberately loud and non-dismissible: the terminal is styled to look like a live institutional product and a demo session is showing simulated prints.
- Tests cover the flow engine (`quantflow-modules/flow-engine`, 18 tests) and the backend seams (`backend/test`, 266 tests: the adapter, the health-error formatter, the enrichment latch, the demo-mode gate, the connector credential table, the vendored-copy mirror guard, the prohibited-host scan, the dead-source guards, the Blueprint drift check, the socket handshake gate, the frontend wire contracts (now including the news page's three panels and the normalized news wire), plus the rights registry, the connector gate, signal identity/decision time, the store, the recorder, the grader, and an end-to-end history integration suite) — both `node:test` via `tsx`. `npm run verify` in `backend/` runs typecheck (src **and** test, via `tsconfig.test.json`) then the suite.
- **`frontend/test/` is Vitest + Testing Library (91 tests), and covers what the backend suite structurally cannot.** `wireContract.test.ts` reaches across the directory boundary and matches text against source, which catches a field name drifting from the API; it cannot catch a field read correctly and *displayed* wrongly. That is how `cryptoPrice` shipped rendering SHIB at 0.0000058 as **$0.0000** — caught by eye in a screenshot, not by a test. The formatters now live in `lib/format.ts` (they were module-local inside `app/macro/page.tsx`, so untestable by construction), and the component tests render against **the same recorded fixtures** in `backend/test/fixtures/`. Config is `vitest.config.mts` — `.mts` because `@vitejs/plugin-react` is ESM-only, with `esbuild: { jsx: 'automatic' }` because `tsconfig.json` sets `jsx: preserve` for Next and Vitest has no Next. It runs `pool: 'forks', singleFork` deliberately: the default worker pool starts a jsdom per thread and will not fit alongside a Next build on a small box, and a suite that cannot be run is worth nothing.
- **The flow event wire shape is `frontend/lib/types.ts` `FlowEvent`** — snake_case, shared by `/api/flow` and the `flow_batch` socket event. (Before the engine integration the backend emitted an unrelated camelCase shape that the frontend silently failed to read.) Change it in both places at once; `getFlowStats()` and `routes/flow.ts` filter on these field names and would return empty results, not errors, if they drift.
- **`ClassifiedSignal.ts` is the FIRST print in the cluster and is deprecated for any measurement.** A signal assembled from a 500 ms burst was not actionable at that burst's first tick, so measuring an outcome from there hands the backtest the burst duration plus the feed latency as free information and every excursion comes out flattering. Use `decisionAt`. The invariant `decisionAt >= lastEventAt >= firstEventAt` is enforced in `identity.ts` (throws), in the store, and as a `CHECK` constraint. Signals with no receipt clock (replay) get `decisionBasis: 'EVENT_TIME_ONLY'` — a lower bound crediting zero latency — and are excluded from published rates rather than pooled with observed ones.
- **A signal's identity is its content hash, not `ClassifiedSignal.id`.** The engine id is `sig_<seq>_<ts>` and the sequence restarts at 1 on every process boot, so it is bookkeeping only. A duplicate key carrying *different* content is a `HISTORY_COLLISION`: recorded as an incident, and the stored row is kept. Treating it as idempotent — the usual default — silently accepts a rewrite of recorded history.
- **`/api/track-record` publishes no rate below n=30 graded outcomes** (`INSUFFICIENT_SAMPLE`), excludes synthetic signals entirely while counting them where a reader can see them, and reports `UNGRADED` outcomes rather than dropping them. Most `UNGRADED` rows are `AMBIGUOUS`-side signals — the ones a less careful system would guess a direction for. Adding a connector means adding its `source` string to both `SOURCE_TO_DATASET` and `INGESTION_SOURCES` in `test/rights.test.ts`; an unmapped source is refused silently, which reads as "nothing is being recorded".
- **A connector whose dataset is `PROHIBITED` for `DISPLAY` is never started.** `mayOperateConnector()` in `provenance/rights.ts` is the gate; `startConnector`, `startCboeOptions` and `startOcc` consult it *before* calling `start()`, because `start()` is what issues the request and the request is the act the terms forbid. The source then reports `refused` on `/api/health` — a **fourth status**, distinct from `disabled` (no credentials) and `error` (the vendor said no), so nobody tries to fix it with an API key — and `ingestion.rightsRefusals` carries the quoted restriction, the terms URL and the read date. Today that is Yahoo alone. There is deliberately **no override env var**: a bypass over an established, quoted prohibition lets the refusal be switched off by whoever is least likely to have read the terms.
- **The gate is narrower than `classify(id, 'DISPLAY')` on purpose, and must stay that way.** It refuses `PROHIBITED` only. `UNVERIFIED` sources (CBOE, OCC, FINRA) keep running and keep reporting their class — the registry's own reasoning is that an unverified source "is a much worse basis for a permanent record than for an ephemeral panel", and the Cboe entry concedes the asymmetry when it says `PERSIST` is refused "anyway". If the gate refused `UNVERIFIED` too, `DISPLAY` and `PERSIST` would resolve identically for every dataset and the two-axis design would be dead code; `test/connectorGate.test.ts` has a canary that fails if that ever happens. An **unregistered** source is not stopped either — FRED, CoinGecko, Reddit, NewsAPI, Stooq, TwelveData, FMP and FlashAlpha emit no prints and have no dataset entry, and refusing them here would take out the macro/news/sentiment pages over a registry coverage gap rather than a rights finding. They remain refused for `PERSIST`, which is where an unregistered source actually does damage.
- **The root `render.yaml` is the only Blueprint, and it is checked against the code.** `backend/render.yaml` was a second, stale copy declaring the same service — no `BUSINESS_MODE`, a pinned `PORT` (Render injects it), and none of the connector credentials — so whichever one Render was pointed at, the other was a trap. It drifted in both directions and neither was visible from inside the code: fourteen free-tier connector credentials were read by `src/ingestion/connectors/*` and declared nowhere, so a Blueprint deploy had no slot for them and those sources reported `disabled — no credentials` in production with no dashboard fix; while `ALPACA_KEY`/`ALPACA_SECRET` (there is no Alpaca connector) and `UPSTASH_REDIS_REST_URL`/`_TOKEN` (the rate limiter is in-memory and no redis client is installed) were declared, documented in the README and `.env.example`, and read by nothing. `renderBlueprint.test.ts` fails on either direction. **`YAHOO_ENABLED` is deliberately undeclared** — the rights gate refuses that connector before `yahoo.ts` reads the flag, so an entry would advertise a switch that does nothing.
- **A source that is down must never present itself as data**, and three of them were. Stooq answers with a JavaScript browser-verification page instead of its CSV (HTTP **200**, HTML body) — the parser's only guard was `lines.length < 2`, which a four-line challenge page clears, so twelve quotes with `close: 0` were cached every ten minutes while `/api/health` said `connected`. Cboe's `options_volume.json` returns **403**, and a bare `catch {}` plus `?? 0` turned that into an equity put/call ratio of `0.00`, coloured green. The frontend then covered for both with hardcoded `FALLBACK` arrays — Fed Funds 5.33%, BTC $67,420, ES 5787.50 — rendered through the same markup as live data. The rules now: **a connector reports its own health each cycle** (`onStooqHealth`; `startConnector` only records what `start()` returned once, and no longer overwrites a failure the connector already reported), **an unavailable value is `null`, not `0`** (`CBOEData.putCall*`, with `putCallUnavailable` saying why), and **a panel with no data names the missing source** instead of inventing one. This is not the `synthetic: true` case — simulated prints keep the terminal functional and are excluded from the track record by name; a hardcoded Fed Funds rate has neither role nor exclusion.
- **Every `/api/macro` consumer had the wrong wire shape, and each failure was silent.** The page read Stooq off `/api/macro/quotes` (which is TwelveData spot, not Stooq) and type-guarded the response away with `Array.isArray` against a `{ quotes: [...] }` body; the same `Array.isArray` mistake dropped CoinGecko's live quotes; `VIXData.timestamp` did not exist (the route sends `updatedAt`), so the panel rendered **"Invalid Date"** whenever data was real and a valid clock only while the fallback was up; `pcr`/`pcrIndex` did not exist either; and `StooqQuote` declared `price`/`change`/`changePct` against a wire carrying a daily OHLC bar, so `q.price.toFixed(2)` would have thrown the moment anything arrived. Two bugs were cancelling into an empty panel. **The route is the contract and the page follows it** — same rule as `FlowEvent`. `sessionChange` is named for what it is (close against the same bar's open, not day-over-day); `change24h` on the crypto wire is absolute and `changePct24h` is the percentage.
- Side inference is `AMBIGUOUS` whenever the NBBO is missing, **stamped after the trade**, or stale, and that carries a -15 score penalty — it is a deliberate honesty contract, not a bug. The look-ahead half was a hole until now: the staleness gate is a subtraction (`tradeTs - nbbo.ts > maxAgeMs`), so a quote from *after* the trade produced a negative age and sailed through, letting the engine read a print's direction off an NBBO that may already reflect that print. Nothing exercised it while every source published the quote carrying its own trade's `ts` — an independent quote feed is what changes that. Same class as measuring an outcome from the first print instead of `decisionAt`.
- **`backend/test/vendorMirror.test.ts` enforces the vendoring obligation** that was previously only described here. It compares `backend/src/flow-engine` against `quantflow-modules/flow-engine/src`, and `backend/src/enrichment/firecrawl` against its module, modulo import-extension stripping. Two divergences are **declared** — `resetDaily()` and the firecrawl vendoring header — written as precise strips rather than per-file exemptions, so nothing else can hide behind them. It found real drift on its first run: two comment edits made in `flow-engine/types.ts` and never mirrored, since fixed. The Polygon trades path fetches its NBBO separately, bounded by `timestamp.lte` at or before the trade's own nanosecond timestamp — asking for the *current* quote would be useless against the 2s window and look-ahead against an older print. The quote is published under **its own** timestamp via `RawPrint.quoteTs`, not the trade's, because stamping a five-second-old quote as simultaneous manufactures the freshness the staleness rule exists to judge. Lookups are deduped per contract and capped at `POLYGON_QUOTE_BUDGET` per cycle: 25 trades a poll against a vendor whose free tier allows five calls a minute. A quote failure sets `sourceNotes.polygon` rather than flipping the source to `error` — plans commonly include trades and not quotes, and a connected-but-non-directional feed is invisible if the only vocabulary is connected/error. **No call has ever been made against real Polygon from this repo; the integration is covered by stubs only.** Chain-snapshot connectors (marketData, schwab, tastytrade, yahoo) synthesize prints from aggregate volume and are flagged `synthetic: true` on the wire.
- `heatScore.ts` / `sweepDetector.ts` are superseded by the flow engine. Four connectors still import them to build their own events, but those values are discarded by the adapter — do not add new callers.
- **Nothing in the browser manufactures flow.** `useFlowFeed` used to seed the store with 50 events from `generateSeedFlow` on mount — random tickers, premiums to $15M, heat drawn uniformly from 40 to 100, spot prices hardcoded at 2024 values — and invent one more every eight seconds while the socket was down. The seeded fifty went in via `addFlowBatch` and only misinformed the reader. **The eight-second ones went through `handleEvent`**, which raises a power alert at heat 75, *speaks the trade aloud* above 80, and fires an *OS push notification* above 85 — so a terminal with no market-data connection was announcing sweeps that had not happened, out loud and onto the desktop. Deleted rather than flagged: `synthetic` would have made the badge appear and left the speech and notifications firing, since neither `speakAlert` nor `pushNotification` reads that field, and the backend already simulates prints with the flag set where the UI can see it. `speakAlert`/`pushNotification` are untouched — the bug was what fed them.
- **A display filter was deleting the tape.** `useFlowFeed.handleEvent` began `if (!passesFilters(event)) return`, so the store held only what matched the filters **at the moment each signal arrived** — and the filters are a view control the reader moves. Raising `minPremium` to $1M for a minute and putting it back deleted every sub-$1M print from that minute, permanently, while the control on screen said they were admitted again; widening cannot recover what was never kept. The predicate was written out twice, once at ingest and once inline in `FlowFeed`, so the display copy re-filtered an already-filtered set and was a no-op for anything but a narrowing: dead code guarding against a loss the other copy had already caused. `lib/flowFilter.ts` is the single `matchesFilters`, applied at display only, source-scan guarded the way `STALE_MS` is. **Alerts no longer sit behind that gate.** `addPowerAlert`, `speakAlert` and `pushNotification` all ran inside it, so choosing to look at puts stopped the terminal announcing a $10M call sweep and a `$1M+` filter stopped a heat-95 print at $800K from ever being spoken — a view control with an invisible side effect on an out-of-band channel, which is the shape of the finding that got the seeded feed deleted rather than flagged. `isPowerAlert` is `is_unusual && heat_score >= 75`; the speech (>80) and push (>85) thresholds are unchanged. `pushNotification`'s guard was `typeof window === 'undefined' || Notification.permission !== 'granted'`, which **throws a ReferenceError** wherever the API is absent but `window` is not (iOS Safari, embedded webviews, jsdom) — inside the socket's batch handler, so one heat-86 print took the whole feed down there. `PowerAlert.alert_type` declared `SWEEP|BLOCK|DARK_POOL|GEX_FLIP|ML_SIGNAL` while `useFlowFeed` assigned `event.order_type as any`: three of those five were produced by nothing (`ML_SIGNAL` was the deleted ML service's slot, `ml_score`'s sibling) and three of the values actually arriving were not in the union; it is `OrderType` and the cast is gone. **The stat tiles said TOTAL and meant "the last few hundred signals"** — `flowEvents` is a 500-event client ring buffer filled from page load, and the backend's buffer caps at 500 too, so `/api/flow/stats` would not have made the word true. They now say what they are over, including the window's span, whether it is full, and **how many prints in it are simulated** (the per-row badge and the all-or-nothing demo banner cover neither an aggregate nor a mixed credentialed deployment). `P/C RATIO` was `putPremium / callPremium` while `/api/flow/stats` published `callPutRatio` as a *count* ratio the other way up and the macro page's Cboe put/call is exchange volume — three quantities, one label; the tile is `PUT/CALL $` and the endpoint's field is `callPutCountRatio` (and `null`, not `0`, with no puts). An all-put tape used to render `'—'` in **green**, because `Number('—') > 1` is false. The CSV export writes the filtered view and now says so in two comment lines, and carries `synthetic` per row, because a spreadsheet cannot see the badge.
- **The power alerts page described a trigger the code does not implement, and credited a model that does not exist.** "AI-scored unusual activity · Heat ≥75 · SWEEP + Block alerts": there is no model — `heat_score` is `flow-engine/score.ts`, deterministic, publishing its own per-component breakdown — and `ml-service/` was deleted for putting a number with no provenance beside a real signal, taking this page's `ML CONFIDENCE` line with it. BLOCK is special-cased nowhere and a SWEEP raises nothing on its own; the empty state was wrong a third way, promising "Heat ≥75 **or** unusual SWEEP" where the condition is the conjunction `is_unusual && heat_score >= 75` on any order type. `ALERT_TYPE_COLORS` carried `DARK_POOL`, `GEX_FLIP` and `ML_SIGNAL`, produced by nothing, and is now keyed `Record<OrderType, string>`. **An alert did not know whether its print was real.** The backend simulates prints on every keyless deployment, and one clearing the threshold was rendered, **spoken aloud** and **pushed to the desktop** unmarked — the exact gap this file already names about the deleted seed generator, that neither `speakAlert` nor `pushNotification` reads `synthetic`. `PowerAlert` now carries `synthetic` and `score_breakdown`; the speech says "Simulated" first (before the ticker, because a listener who looks up mid-sentence has already missed it), the notification title carries `🧪 SIMULATED ·`, the row and the always-on `PowerAlertBanner` carry a badge, and the page counts them once at the top. The notification title also **hardcoded `SWEEP`** while the event carries its own `order_type`, so a BLOCK arrived on the desktop announced as a sweep. The 22px heat score now shows the engine's `score_breakdown` beneath it — `ml_score`'s resolution applied to the number that replaced it — and the empty state distinguishes a disconnected feed from a quiet one. `PowerAlertBanner`'s voice button had `fontFamily: "'JetBrains Mono', monospace' "`, a stray quote voiding the declaration: the watchlist's `marginTop`-inside-the-font-string slip, in a second file.
- **An empty store is now reachable, so every page built from one needs an empty state.** The seed made that impossible before, which is why the heat map had none at all and rendered a bare grid. The flow feed distinguishes the three cases rather than saying "no data" to all of them: socket refused (a configuration answer — see the gate), backend unreachable (an outage), connected and quiet (a slow tape).
- **The GEX chart reads `/api/gex`; it used to invent one.** With no flow events for the selected ticker it drew twelve strikes of `Math.random()` — including `level_type: Math.random() > 0.5 ? 'SUPPORT' : 'RESISTANCE'`, deciding by coin flip whether a strike was support or resistance — and with flow events it aggregated open interest off whichever individual prints had arrived, times a gamma of `Math.abs(e.delta * 0.01) || 0.005`. Neither is dealer gamma exposure; both were drawn in the same colours beside a spot price hardcoded to 2024 values. The route has always returned the real thing (445 strikes for SPY with per-side OI and gamma from Cboe's delayed chain, a computed `flipStrike`, `keyLevels`) plus `source`/`realData`/`delayedMinutes` — its own comment says why: *"The UI must be able to tell them apart — a fabricated gamma flip looks exactly like a real one."* It now honours `realData` and draws nothing when the backend has no chain, and carries the provenance badge, since `CBOE_CDN_DELAYED_CHAIN` is UNVERIFIED for display.
- **The ticker tape reads `/api/macro/quotes`; it used to make the prices up.** `TopBar` is mounted in `app/layout.tsx`, so its strip is above the fold of *every* page — and it held a hardcoded base map (SPX 5587, NVDA 942, TSLA 182, all 2024 levels), added `Math.random() * 4 - 1.5` per symbol, and re-rolled the board on a `Math.random() > 0.7` coin flip every ten seconds, in the same monospace and the same green and red as the live panels beneath it. A reader who had just been told the GEX chart draws nothing without a real chain was being shown an invented NVDA quote two inches higher. Same family as the seeded flow feed, the generated dark-pool prints and the coin-flipped support/resistance levels, and the most-seen member of it. The symbols now come from the response rather than a `TICKERS` const — the old list held fifteen against a feed covering ten, so seven could never have had a price behind them, which is the failure the settings page retired three hand-maintained lists over. Three states are distinguished because they have three different answers: signed out (an empty strip — the tape mounts on `/login` too, and a banner there is noise about nothing), the route answering with `{quotes: []}` (**every keyless deployment**, which says so and points at Settings rather than naming an env var — the per-source status lives there and a second copy would be a second copy to keep correct), and the backend not answering. `MarketSnapshot` in `frontend/lib/types.ts` is replaced rather than left beside the new type: it declared `ticker` against a wire whose key is `symbol`, imported by nothing, one import away from rendering `undefined` down a column — the `ml_score` hazard.
- **A cached quote is dated once it stops being current, and that took fixing `SpotQuote.timestamp` first.** The connector caches, so a dead TwelveData feed keeps serving its last board forever; rendering that in live styling is the Stooq failure with a different connector. The tape marks anything older than five minutes `AS OF <time> ET` and dims it. That was unbuildable as written: the WebSocket path wrote TwelveData's stamp straight through — unix **seconds** — while `fetchQuotesBatch` wrote `Date.now()`, **milliseconds**, into the same field of the same cache. Nothing had ever read it, so nothing broke; the first consumer would have dated every streamed quote to 1970 and left the REST ones correct, dimming half the board over a unit error. `quoteTimestamp()` normalizes at the boundary (below 1e12 is seconds; a missing or unparseable stamp is receipt time, never zero) and `deadSources.test.ts` asserts **both** write paths go through it — a test of the function alone passes just as happily with the WebSocket handler still bypassing it. The REST path now publishes the vendor's own stamp where it sends one, rather than overwriting it with receipt time: same rule as `RawPrint.quoteTs`, and stamping last session's close as if it arrived now manufactures exactly the freshness the staleness check exists to judge.
- **The tape's 2024 price map survived in two more files, and one of them read it once.** Deleting `generateQuotes()` took the copy in `TopBar`; `app/watchlist/page.tsx` kept fifteen levels in `SPOT_PRICES` (SPX 5587, SPY 557, NVDA 942, TSLA 182) and rendered them under each ticker in the same monospace as the flow statistics beside them — the same map with the `Math.random()` jitter left off — and `components/calculator/StrategyBuilder.tsx` kept eight in `SPOTS` and priced **every Black-Scholes leg** off them. Five of the watchlist's fifteen (MU, MRVL, IWM, GLD, SOXL) are not symbols TwelveData's `WATCHED` covers, so they could not have been right even in 2024: a hand-maintained list in front of a feed, which is what cost the tape seven tickers and the settings page three lists. The builder's copy was read **once**, into `useState`'s initial value, so changing the selected ticker left the previous underlying's spot *and its first leg's strike* in place — the panel said NVDA at the top and priced SPY underneath. **`lib/spotQuotes.ts` is now the one reader of `/api/macro/quotes`**, and `POLL_MS`/`STALE_MS` live there rather than in `TopBar`, because three components dating a stale quote is three places for "five minutes" to drift. With no quote there is no substitute: the watchlist card shows no price (the tape above the fold already says whether the feed is empty, refused or unreachable, and a second copy of that message is a second copy to keep correct), and the builder asks for a spot, disables **+ Add Leg** — a leg needs a strike and a strike is chosen around the spot, which is how `SPOTS[selectedTicker] || 100` came about — and draws no P/L curve, since a curve centred on a stand-in is a picture of a position nobody holds. The builder also names its source on screen (`FROM NVDA 1,204.55`, `· AS OF … ET` when stale, or `YOUR OWN ASSUMPTION` once edited). A broken inline style on the watchlist card (`fontFamily: "'JetBrains Mono', monospace', marginTop: 2"` — the margin written inside the font string, voiding both) went with it.
- **Selling was a no-op in the P/L calculator, and a bought call was drawn with no downside.** `computePLCurve` decided a leg's direction with `leg.qty > 0`, while the quantity input clamped to `Math.max(1, …)` with `min={1}` — so the test was true for every leg that could be built and the `ACTION` select changed **nothing**. A sold contract produced a byte-identical curve to a bought one, and with it the same max profit, max loss and breakeven. On top of that `entryPrice` defaulted to `0`, so the curve plotted the position's *value* rather than its P/L: at the page's own defaults a long call reported **MAX PROFIT $18,252, MAX LOSS $0, BREAKEVEN —** and **PREMIUM PAID: Credit** — no downside on a position costing $2,346, and an assertion that the reader had been paid to open it. `PREMIUM PAID` read `total > 0 ? $total : 'Credit'`, and "nothing entered yet" is a third state that was being rendered as the second. **`lib/payoff.ts` is the payoff at expiry**, kept apart from `blackScholes.ts` because that module values a position *before* expiry under a model and this one is arithmetic on the settlement payoff. `extremes()` evaluates the exact kinks (`S = 0` and each strike) rather than `Math.min`/`Math.max` over a 0.70x–1.29x sample — which reported a naked short call's loss as a finite number that was a fact about where the plotted range stopped — and returns `null` for an unbounded tail, decided by `netCallUnits` (puts cannot make one; the underlying stops at zero). `breakevens()` solves them by interpolating across the segment that contains each root, which is **exact** for a piecewise-linear payoff, and returns all of them: the tile printed `breakevens[0]`, read off sign changes in a 60-point sample of the *model* curve and rounded to whole dollars, which is a wrong answer for a straddle. The chart draws two named series — the payoff at expiry, which the heading had always claimed, and `computePLCurve` as "today", which is what was actually plotted and is the curve the DTE slider moves. `entryPrice` seeds from the model and the field says `· MODEL` until edited, the way the spot field names its source. `r = 0.05` was a default parameter of `computePLCurve` **and** a second copy inline in the Greeks call, so the two could have disagreed and neither was on screen; it is one labelled input. `qty` stays unsigned — direction lives in `action` and only there, or there would be two ways to say the same thing and a new way for them to contradict.
- **The dark pool page reads `/api/darkpool` and renders the backend's own `notice`/`disclaimer`.** It used to call `generateDarkPool()` — random tickers, sizes and exchanges (including `DARK_NYSE`, not an exchange code), prices hardcoded at 2024 values, a fresh invented print pushed in every 20s — under a hand-written **⚠ 24-HOUR DELAY** badge asserting a regulatory fact about prints nobody had observed. Note that wiring the endpoint does **not** make the page real: the backend's prints carry `source: 'simulation'` with no vendor feed configured. What changed is that the page stops asserting, renders the regulatory language the backend actually publishes, and marks simulated rows per row.
- **The news page invented its own newsroom, and two of its three panels could never have shown anything else.** The fetch tested `Array.isArray(body)` against `{ headlines: [...] }` and `{ earnings: [...] }` — the envelope mistake that emptied the macro page — so the live arrays were empty on *every* deployment, keyed or not, and `headlines.length > 0 ? live : FALLBACK` always took the second branch. What the fallback held is what raises this above the rest of the family: six fabricated headlines attributed **by name** to Reuters, Bloomberg, CNBC, MarketWatch, the WSJ and Barron's, timestamped backwards from `Date.now()` so they always read as minutes old; six fabricated Reddit posts in quotation marks with four-figure mention counts; five fabricated earnings dates with EPS estimates to the cent. The seeded flow feed and the hardcoded tape fabricated numbers; this fabricated reporting and put real newsrooms' bylines on it. The Reddit panel failed a third way — it found the right key and described a record the wire has never sent (`sentiment`, `bullishPct`, `bearishPct`, `topPost`, `lastUpdated`: five fields, zero of them real), so live data would have rendered `undefined% bull`, `NaN% neutral` and a gauge at `width: NaN%`. **`sentimentScore` runs -100…+100**, and every consumer was calibrated for -1…+1 — binding the right field without rescaling typechecks and calls a mild 30 "VERY BULLISH" at 1550% width, which is the `wireContract` blind spot exactly. `bullishMentions`/`bearishMentions` are **keyword hits summed over posts**, not post counts and not shares of `mentions`; they can exceed it, so they are rendered as tallies and the percentage split is gone. `/api/sentiment/news/headlines` was itself malformed: it concatenated NewsAPI's records with FMP's under one key, and the two share no field that matters — FMP has `symbol` where NewsAPI has `symbols[]`, `publishedDate` where NewsAPI has `publishedAt`, no id, and the literal `'fmp'` where NewsAPI puts the outlet's name. A client typed for either half calls `symbols.length` on `undefined` and unmounts the page — a crash waiting on an `FMP_API_KEY`, not on a code change. `toNewsWireItem()` resolves that union at the boundary (`publisher` and `provider` split apart) so the route publishes one contract, on both news paths; `backend/test/newsWire.test.ts` drives it with values typed as the connectors' own interfaces. Panel state is `lib/panel.ts` — `loadPanel` checks `res.ok` **before** the body, because a 401 parses as JSON and arrived `fulfilled` through `Promise.allSettled`, collapsing signed-out, keyless and backend-down into one blank. Three endpoints, three independent credentials, three independent statuses. A refusal is **not** worded "signed out", which is where the tape's copy would have led: the tape mounts on `/login`, but `middleware.ts` gates `/news` behind a session or the demo cookie, so a reader seeing this page has one — a 401 here is an expired token, a backend with no Supabase client (the boot warning in `server.ts`), or a demo cookie against a backend without `DEMO_MODE`. Two of the three are deployment faults and "sign in" sends the reader after the wrong one, which is the heat map's own finding about answering "no data" to two different problems. The aggregate sentiment pill is gone unless something answered: it defaulted to `0.1` and published a NEUTRAL market read computed from nothing.
- **`synthetic` is shown per row in the flow feed.** The backend has set it all along — on simulated prints, on replay, and on the chain-snapshot connectors that construct a print from aggregate volume — and the terminal never displayed it. The demo banner is all-or-nothing and cannot cover the case that matters: a credentialed deployment where some rows are observed tape and some are constructed, side by side.
- **`backend/test/wireContract.test.ts` checks the frontend's types against recorded responses.** Every UI bug found here has been the same one — a page reading a field the API does not send, failing silently — and none is catchable by typechecking, because the frontend's interfaces are assertions about a separate process. The fixtures in `test/fixtures/` are real payloads produced by `preview:capture`, not hand-written ones that would drift the same way the interfaces did. Re-record them with `npm run preview:capture -- --out test/fixtures`.
- **There is no ML service, and `ml_score` is not a field.** `ml-service/` was a FastAPI app with its own Render slot exposing `/score` for "unusual flow scoring", and nothing in `backend/src` ever called it. It could not have been trusted if it had: `train.py` drew the label first (`is_unusual = rng.random() < 0.25`) and then sampled features from two hand-written distributions conditioned on it, so a classifier fit to that data recovers the author's own branch and nothing about markets — `np.random`, seed 42. The dangerous part was the socket left for it: `PowerAlert.ml_score` was on the wire and `power-alerts/page.tsx` rendered `ML CONFIDENCE: N%` gated on `> 0`, so the next assignment to that field would have shipped a confidence with no provenance, in green, beside a real signal. Field and renderer are removed with the service. **Scoring is `flow-engine/score.ts`** — deterministic, and carrying per-component `score_breakdown` on the wire, which is a strictly better thing to show than an opaque number. If a model is ever wanted, `collection:doctor` names exactly what is missing to train one on real graded outcomes; that path is blocked on data, not code.
- **`backend/tools/collection/doctor.ts` answers "would a signal recorded now ever be graded?"** `/api/track-record` reports `total: 78, synthetic: 78, real: 0` with a grader that has tracked nothing. That is correct output and its notes say so — but it cannot say *why*, and the why is **four independent conditions plus a hosting hazard**, all of which must hold before one graded outcome exists: a source PERMITTED for PERSIST in the running mode **and** credentialed; `SUPABASE_URL`/`SUPABASE_SERVICE_KEY` for durability; **`TWELVE_DATA_API_KEY`**, because `getSpotPrice` is the grader's only mark source and without it every outcome is `UNGRADED` ("No usable entry mark"); and a process that outlives the 15-minute M15 checkpoint, which Render's free tier does not. The third is the one nobody guesses — a deployment can have a licensed options feed and durable storage and still grade nothing, because the mark comes from a different connector. The doctor reports **all** failures rather than the first, since fixing a subset changes nothing observable. Nothing here is about the code: `historyIntegration.test.ts` already drives a real print to a POSITIVE M15 outcome. It is about a deployment being silently unable to collect.
- **`CONNECTOR_CREDENTIALS` now covers all sixteen connectors.** Tradier, Polygon and Finnhub start on their own paths rather than through `startConnector` and were omitted for that reason — so nothing could answer "which variable turns Tradier on". The doctor asked and got `(none listed)` for the two most likely options feeds. `connectorCredentials.test.ts` maps them to `ingestion/index.ts`, where they are implemented inline.
- **`backend/tools/preview/` runs the UI without running the stack.** The backend is ~320MB of ingestion pipeline and `next dev` another ~300MB; a browser on top of both does not fit on a small box. `capture.ts` records a live backend's REST responses, `serve.ts` replays them beside the frontend's production build from **one origin**, so same-origin `/api/*` resolves with no proxy. Two things make it worth trusting: the data is recorded verbatim rather than hand-written, so it cannot drift from the API it describes; and the socket gate is **imported** `authenticateSocket`, not a reimplementation — a preview that approximated it would be the second copy this repo has a whole test suite about. It needs `DEMO_MODE=1` to serve the feed, because the gate is the real one, and it says so at startup rather than leaving you guessing. Captures land in `.preview/` (gitignored). Entitled endpoints — `/api/chain`, the enrichment routes — are never captured. `tsconfig.test.json` typechecks `tools/**` so a change to `authenticateSocket`'s signature breaks here rather than at someone's next demo.
- **Showing the UI on ChromeOS/Crostini:** `xdg-open` is the generic freedesktop script in the container and fails silently. `/opt/google/cros-containers/bin/garcon --client --url "http://localhost:3360/flow/"` is the handler that reaches the host browser — and rendering on the host means the container's memory ceiling does not apply.
- **The settings page reads `/api/health`; it does not collect keys.** It used to render twenty-one password inputs over a save handler that was `setSaved(true)` and nothing else — you pasted a Tradier token, were shown "✓ KEYS SAVED", and the value was discarded on the next navigation. Implementing that save would not have helped, which is the actual finding: connectors read their credentials **once at module load** into module-level consts, and there is one process-wide ingestion pipeline emitting one global `flow_batch`, so there is no per-user key path to write into. `supabase/schema.sql` has an `api_keys` table (RLS policies, index, trigger) that nothing reads or writes and that cannot work without making ingestion per-user; its plaintext `key_value` is documented as such rather than dropped, because that file is run by hand and what is deployed cannot be verified from the repo. Every status on the page now derives from `sources` / `sourceErrors` / `rightsRefusals`, which retired three hand-maintained lists that had each been corrected twice as sources changed state — and were wrong in between. The page also listed Alpaca and Alpha Vantage keys, and `CBOE_ENABLED`, none of which exist in the backend.
- **Every connector that reports `disabled` names the variable that would enable it.** `startConnector` did this for the thirteen from `CONNECTOR_CREDENTIALS`; Tradier, Polygon and Finnhub start on their own paths and set `sources[x] = 'disabled'` with no reason, so `/api/health` reported three sources as off while naming nothing actionable. `markNoCredentials()` is the shared path, and `connectorCredentials.test.ts` fails on a bare `sources[...] = 'disabled'` assignment.
- **The Socket.IO feed is gated at the handshake, on the same terms as `/api/flow`.** It was the one door with no lock: every REST route sits behind `requireAuth` or `requireAuthOrDemo`, and `/api/flow` serves exactly the signals the socket broadcasts — but `io.on('connection')` admitted anyone who connected, with `cors.origin: '*'` and `credentials: true`, so any page on any origin could open a socket and receive `flow_batch` in real time. `authenticateSocket()` lives in `middleware/auth.ts` beside the middleware it mirrors so the two tiers cannot drift, and `io.use()` applies it during the handshake rather than after the connection is established. Same two independent conditions as the HTTP tier: a demo socket needs `DEMO_MODE=1` **and** the client to ask. The refusal reason is deliberately just `Unauthorized` — it crosses to an unauthenticated caller and must not say which condition failed. Socket CORS is now `CORS_ORIGINS`; unlike the HTTP path (which arrives via the frontend's server-to-server rewrite and sends no `Origin`), `NEXT_PUBLIC_WS_URL` points the browser straight at the backend, so origin genuinely matters there.
- **`frontend/lib/socket.ts` passes `auth` as a callback, not an object, and that is load-bearing.** socket.io re-invokes it before every connection attempt, so a reconnect picks up the current Supabase access token. A plain object would freeze whatever token existed when the module-level singleton was built; tokens are short-lived, so the socket would work until the first network blip and then fail its handshake with an expired token. A page reload always looks fine, which is what makes that failure easy to ship. `onAuthStateChange` also reconnects on sign-in/out/refresh, because the server does not re-evaluate an established socket's identity.
- **A refused feed and a down backend look identical in the UI.** `useFlowFeed` substitutes simulated prints for both, so the terminal keeps rendering and does not look broken. That is why `server.ts` warns at boot when neither a Supabase client nor `DEMO_MODE=1` exists — every socket will be refused, and nothing on screen will say so.
- Simulation/fallback mode means the app is fully functional without any live market-data API keys configured; don't assume missing keys are a bug when testing locally.
- `sourceErrors` in `/api/health` is served **unauthenticated**, so every string that reaches it is public. `src/ingestion/httpError.ts` is the one place that formats a vendor failure for it: it carries the vendor's own response body through (a hardcoded guess about *why* a source is down is how that route ended up confidently wrong) and scrubs anything credential-shaped on the way out. Use `describeHttpError` for new connector failures rather than hand-rolling a string, and keep connector keys in headers rather than query strings.
- Enrichment responses carry `context_only: true` and a `disclaimer` field. That is an honesty contract of the same kind as `synthetic` and `side: AMBIGUOUS` — Firecrawl news is a context layer and must never be presented as a trade trigger. Keep it on the payload; a comment does not reach an API client.
- The enrichment routes are registered **above** `/:symbol` in `routes/sentiment.ts`. That route matches any single path segment, so a single-segment route declared after it is captured as a ticker symbol.
- `/api/sentiment/regulatory/:slug` resolves against a server-side allowlist rather than accepting a `?url=`. A caller-supplied URL would make an authenticated endpoint into a request forwarder billed to this account — SSRF and credit drain in one. Adding a source is a code change.
