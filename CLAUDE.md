# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Architecture

QuantFlow Pro is an options-flow terminal split into three independently deployed services plus Supabase:

```
Next.js 14 frontend (Vercel)  <-- REST + Socket.IO -->  Node/Express backend (Render)  -->  Python FastAPI ML service (Render)
                                                                    |
                                                              Supabase (Postgres + RLS)
```

- **`frontend/`** — Next.js 14 App Router, TypeScript, Zustand (`store/useStore.ts`) for client state, Socket.IO client (`lib/socket.ts`) for the live flow feed, Supabase SSR client for auth. Routes live under `app/` as one directory per feature (`flow`, `dark-pool`, `gex`, `heat-map`, `calculator`, `optimizer`, `power-alerts`, `watchlist`, `macro`, `news`, `settings`, `(auth)`). `middleware.ts` gates every non-auth, non-`/api` route behind a Supabase session, redirecting to `/login` when absent — or behind a demo cookie when demo mode is on (see the note below).
- **`backend/`** — Express + Socket.IO server (`src/server.ts`). `startIngestion(io)` (`src/ingestion/index.ts`) drives a pull/push pipeline from many market-data connectors (`src/ingestion/connectors/*` — Tradier, Polygon, Finnhub, plus 13 free-tier connectors: FlashAlpha, MarketData.app, Schwab, Tastytrade, TwelveData, FMP, CoinGecko, FRED, Reddit, NewsAPI, CBOE, Yahoo, Stooq). Every source normalizes to a `RawPrint` and funnels through `ingestPrint()` in `src/ingestion/flowEngineAdapter.ts`, which publishes the contract's NBBO, feeds the trade to the flow engine (`src/flow-engine/`), and maps finalized signals onto the wire shape. Signals are batched by `emitSignals` (100ms window) and broadcast as a **single global `flow_batch`**. REST routes under `src/routes/*` mirror the API reference below. When no live vendor keys are configured, ingestion falls back to an always-on simulation mode so the app still functions.
- **`backend/src/flow-engine/`** — the classification + scoring engine, vendored from `quantflow-modules/flow-engine` (the module is ESM; the backend is CJS, so it is copied rather than imported, with relative-import extensions stripped). It is byte-identical to the module apart from an added `resetDaily()`. **Change the engine here, and mirror it to the module** — or the module's test suite stops being a valid baseline for what ships.
- **`backend/src/enrichment/`** — the web-enrichment seam. `firecrawl/` is vendored from `quantflow-modules/firecrawl/src/services/firecrawl` (ESM module, CJS backend, so copied with relative-import extensions stripped — **change one, mirror it to the other**); `index.ts` is what the backend adds around it. Two rules live there and nowhere else: enrichment is **demand-driven, never scheduled** (its calls cost metered Firecrawl credits, so nothing fetches unless a request asks), and `AUTH` / `INSUFFICIENT_CREDITS` **latch the service off** until restart rather than retrying against a key that will not recover. Surfaced at `GET /api/sentiment/context`, `/context/status`, and `/regulatory/:slug`, and reported under `enrichment` in `/api/health`. With no `FIRECRAWL_API_KEY` it reports `disabled` and the rest of the app is unaffected.
- **`ml-service/`** — FastAPI service (`main.py`) exposing `/score` and `/score/batch` for unusual-flow scoring. Uses a trained `GradientBoostingClassifier` (`train.py` → `models/flow_scorer.pkl`) when present, otherwise falls back to a heuristic scorer — training the model is optional, not required to run the service.
- **`backend/src/provenance/`** — the data-rights registry. Every external dataset is classified per business mode and per capability (`DISPLAY` vs `PERSIST`), with the publisher's restriction quoted verbatim and the terms URL/read-date recorded. It **fails closed**: `UNVERIFIED` is refused (uncertainty resolves to refusal, not permission), an unregistered source is refused, and a malformed `BUSINESS_MODE` throws rather than degrading to either branch. `DISPLAY` and `PERSIST` are separate because the risk is separate — reading a delayed quote once is not the same act as accumulating a database out of it. `classify()` is the `PERSIST` decision; `mayOperateConnector()` is the `DISPLAY` one and gates whether a connector runs at all (see the note below).
- **`backend/src/persistence/`** — the durable signal history, and the reason the product can ever have a track record. `identity.ts` computes `decisionAt = max(lastEventAt, receivedAt, emittedAt)` (never `ts`, the first print — see below) and the content hash that is a signal's real identity; `recorder.ts` is the one path from a classified signal to storage and applies the rights gate; `grader.ts` grades M15/H1/D1 outcomes scheduled from `decisionAt`; `memoryStore.ts` is the reference implementation of the policy and `supabaseStore.ts` mirrors it. Store selection is reported in `/api/health` under `history` — a deployment that is silently discarding everything is the failure this module exists to make impossible to have by accident.
- **`supabase/`** — `schema.sql` (source of truth, run manually in the Supabase SQL editor) plus `migrations/` for incremental changes. `gate-proofs.sql` is re-runnable evidence that the signal-history constraints actually refuse what they claim to (`psql -d <db> -f supabase/gate-proofs.sql`; every `ERROR:` in its output is a pass). Tables are RLS-protected; `user_profiles` extends `auth.users`, and `api_keys.key_value` is a plaintext column intended to be encrypted via Supabase Vault in production (not yet wired up — treat as sensitive).
- **`quantflow-modules/`** — `flow-engine/` is the canonical home of the classification engine (sweep/block/split/multi-leg, NBBO side inference, deterministic unusualness scoring, outcome tracking) and holds the engine test suite plus the Polygon replay adapter for validating against real historical tape. It is **now integrated** into the backend via the vendored copy described above. `firecrawl/` is a web-enrichment module (FINRA doc sync, news context, research workflows) and is **now integrated** via a vendored copy at `backend/src/enrichment/firecrawl/` — same arrangement as the flow engine, and the same mirroring obligation. Check whether work belongs here vs. in `backend/src/ingestion` before duplicating logic.
- Root-level `qf-firecrawl (1).zip`, `qf-flow-engine.zip`, `quantflow.zip` are uploaded archives, not part of the working tree — the unpacked, current sources are `quantflow-modules/` and this repo itself.

## Commands

```bash
# Frontend
cd frontend && npm install
npm run dev      # http://localhost:3000
npm run build
npm run lint      # next lint — no test script defined

# Backend
cd backend && npm install
npm run dev       # ts-node-dev, auto-restart, http://localhost:3001
npm run build      # tsc -> dist/
npm start          # node dist/server.js
npm test          # tsx --test test/*.test.ts — adapter/wire-mapping tests
npm run typecheck  # tsc --noEmit

# ML service
cd ml-service && pip install -r requirements.txt
python train.py                              # optional: trains models/flow_scorer.pkl
uvicorn main:app --reload --port 8000

# flow-engine module (canonical source; backend ships a vendored copy)
cd quantflow-modules/flow-engine && npm install
npm test        # tsx --test test/engine.test.ts test/outcome.test.ts
npm run typecheck
```

Environment setup: copy `.env.example` to `frontend/.env.local`, `backend/.env`, and `ml-service/.env` respectively (see README's "Environment Variables Reference" for the full key list per service). The backend's authoritative key list is the root `render.yaml`, held to `src/` in both directions by `backend/test/renderBlueprint.test.ts` — a variable read by no code and a variable declared nowhere are both failures there. Run `supabase/schema.sql` in the Supabase SQL editor before first run (RLS-protected tables; the app expects them to exist).

Deployment: frontend → Vercel (root directory `frontend`, rewrites in `frontend/vercel.json` must point at the deployed backend URL); backend + ML → Render via the root `render.yaml` Blueprint (each service's `rootDir` is set there). Render's free tier sleeps services after 15 minutes of inactivity.

## Notes

- **Demo mode** is a read-only unauthenticated path, **off unless both `NEXT_PUBLIC_DEMO_MODE=1` (frontend) and `DEMO_MODE=1` (backend) are set**. Two independent conditions gate every step, so neither a stray cookie nor a stray header opens anything on its own: `/demo/enter` 404s, the `qf_demo` cookie is ignored by `middleware.ts`, the login button is not rendered, and `requireAuthOrDemo` 401s without `X-QuantFlow-Demo: 1`. **`/api/chain` and the three enrichment endpoints stay on plain `requireAuth`** — they return entitled vendor data or spend metered credits, and demo traffic must never reach them. When adding a route, put it on `requireAuthOrDemo` only if it costs nothing per call. The `DemoBanner` is deliberately loud and non-dismissible: the terminal is styled to look like a live institutional product and a demo session is showing simulated prints.
- Tests cover the flow engine (`quantflow-modules/flow-engine`, 18 tests) and the backend seams (`backend/test`, 202 tests: the adapter, the health-error formatter, the enrichment latch, the demo-mode gate, the connector credential table, the vendored-copy mirror guard, the prohibited-host scan, the dead-source guards, the Blueprint drift check, the socket handshake gate, plus the rights registry, the connector gate, signal identity/decision time, the store, the recorder, the grader, and an end-to-end history integration suite) — both `node:test` via `tsx`. `npm run verify` in `backend/` runs typecheck (src **and** test, via `tsconfig.test.json`) then the suite. `frontend/` has none. Verify frontend changes and route behaviour by running the dev servers and exercising the affected pages manually.
- **The flow event wire shape is `frontend/lib/types.ts` `FlowEvent`** — snake_case, shared by `/api/flow` and the `flow_batch` socket event. (Before the engine integration the backend emitted an unrelated camelCase shape that the frontend silently failed to read.) Change it in both places at once; `getFlowStats()` and `routes/flow.ts` filter on these field names and would return empty results, not errors, if they drift.
- **`ClassifiedSignal.ts` is the FIRST print in the cluster and is deprecated for any measurement.** A signal assembled from a 500 ms burst was not actionable at that burst's first tick, so measuring an outcome from there hands the backtest the burst duration plus the feed latency as free information and every excursion comes out flattering. Use `decisionAt`. The invariant `decisionAt >= lastEventAt >= firstEventAt` is enforced in `identity.ts` (throws), in the store, and as a `CHECK` constraint. Signals with no receipt clock (replay) get `decisionBasis: 'EVENT_TIME_ONLY'` — a lower bound crediting zero latency — and are excluded from published rates rather than pooled with observed ones.
- **A signal's identity is its content hash, not `ClassifiedSignal.id`.** The engine id is `sig_<seq>_<ts>` and the sequence restarts at 1 on every process boot, so it is bookkeeping only. A duplicate key carrying *different* content is a `HISTORY_COLLISION`: recorded as an incident, and the stored row is kept. Treating it as idempotent — the usual default — silently accepts a rewrite of recorded history.
- **`/api/track-record` publishes no rate below n=30 graded outcomes** (`INSUFFICIENT_SAMPLE`), excludes synthetic signals entirely while counting them where a reader can see them, and reports `UNGRADED` outcomes rather than dropping them. Most `UNGRADED` rows are `AMBIGUOUS`-side signals — the ones a less careful system would guess a direction for. Adding a connector means adding its `source` string to both `SOURCE_TO_DATASET` and `INGESTION_SOURCES` in `test/rights.test.ts`; an unmapped source is refused silently, which reads as "nothing is being recorded".
- **A connector whose dataset is `PROHIBITED` for `DISPLAY` is never started.** `mayOperateConnector()` in `provenance/rights.ts` is the gate; `startConnector`, `startCboeOptions` and `startOcc` consult it *before* calling `start()`, because `start()` is what issues the request and the request is the act the terms forbid. The source then reports `refused` on `/api/health` — a **fourth status**, distinct from `disabled` (no credentials) and `error` (the vendor said no), so nobody tries to fix it with an API key — and `ingestion.rightsRefusals` carries the quoted restriction, the terms URL and the read date. Today that is Yahoo alone. There is deliberately **no override env var**: a bypass over an established, quoted prohibition lets the refusal be switched off by whoever is least likely to have read the terms.
- **The gate is narrower than `classify(id, 'DISPLAY')` on purpose, and must stay that way.** It refuses `PROHIBITED` only. `UNVERIFIED` sources (CBOE, OCC, FINRA) keep running and keep reporting their class — the registry's own reasoning is that an unverified source "is a much worse basis for a permanent record than for an ephemeral panel", and the Cboe entry concedes the asymmetry when it says `PERSIST` is refused "anyway". If the gate refused `UNVERIFIED` too, `DISPLAY` and `PERSIST` would resolve identically for every dataset and the two-axis design would be dead code; `test/connectorGate.test.ts` has a canary that fails if that ever happens. An **unregistered** source is not stopped either — FRED, CoinGecko, Reddit, NewsAPI, Stooq, TwelveData, FMP and FlashAlpha emit no prints and have no dataset entry, and refusing them here would take out the macro/news/sentiment pages over a registry coverage gap rather than a rights finding. They remain refused for `PERSIST`, which is where an unregistered source actually does damage.
- **The root `render.yaml` is the only Blueprint, and it is checked against the code.** `backend/render.yaml` was a second, stale copy declaring the same service — no `BUSINESS_MODE`, a pinned `PORT` (Render injects it), and none of the connector credentials — so whichever one Render was pointed at, the other was a trap. It drifted in both directions and neither was visible from inside the code: fourteen free-tier connector credentials were read by `src/ingestion/connectors/*` and declared nowhere, so a Blueprint deploy had no slot for them and those sources reported `disabled — no credentials` in production with no dashboard fix; while `ALPACA_KEY`/`ALPACA_SECRET` (there is no Alpaca connector) and `UPSTASH_REDIS_REST_URL`/`_TOKEN` (the rate limiter is in-memory and no redis client is installed) were declared, documented in the README and `.env.example`, and read by nothing. `renderBlueprint.test.ts` fails on either direction. **`YAHOO_ENABLED` is deliberately undeclared** — the rights gate refuses that connector before `yahoo.ts` reads the flag, so an entry would advertise a switch that does nothing.
- **A source that is down must never present itself as data**, and three of them were. Stooq answers with a JavaScript browser-verification page instead of its CSV (HTTP **200**, HTML body) — the parser's only guard was `lines.length < 2`, which a four-line challenge page clears, so twelve quotes with `close: 0` were cached every ten minutes while `/api/health` said `connected`. Cboe's `options_volume.json` returns **403**, and a bare `catch {}` plus `?? 0` turned that into an equity put/call ratio of `0.00`, coloured green. The frontend then covered for both with hardcoded `FALLBACK` arrays — Fed Funds 5.33%, BTC $67,420, ES 5787.50 — rendered through the same markup as live data. The rules now: **a connector reports its own health each cycle** (`onStooqHealth`; `startConnector` only records what `start()` returned once, and no longer overwrites a failure the connector already reported), **an unavailable value is `null`, not `0`** (`CBOEData.putCall*`, with `putCallUnavailable` saying why), and **a panel with no data names the missing source** instead of inventing one. This is not the `synthetic: true` case — simulated prints keep the terminal functional and are excluded from the track record by name; a hardcoded Fed Funds rate has neither role nor exclusion.
- **Every `/api/macro` consumer had the wrong wire shape, and each failure was silent.** The page read Stooq off `/api/macro/quotes` (which is TwelveData spot, not Stooq) and type-guarded the response away with `Array.isArray` against a `{ quotes: [...] }` body; the same `Array.isArray` mistake dropped CoinGecko's live quotes; `VIXData.timestamp` did not exist (the route sends `updatedAt`), so the panel rendered **"Invalid Date"** whenever data was real and a valid clock only while the fallback was up; `pcr`/`pcrIndex` did not exist either; and `StooqQuote` declared `price`/`change`/`changePct` against a wire carrying a daily OHLC bar, so `q.price.toFixed(2)` would have thrown the moment anything arrived. Two bugs were cancelling into an empty panel. **The route is the contract and the page follows it** — same rule as `FlowEvent`. `sessionChange` is named for what it is (close against the same bar's open, not day-over-day); `change24h` on the crypto wire is absolute and `changePct24h` is the percentage.
- Side inference is `AMBIGUOUS` whenever the NBBO is missing, **stamped after the trade**, or stale, and that carries a -15 score penalty — it is a deliberate honesty contract, not a bug. The look-ahead half was a hole until now: the staleness gate is a subtraction (`tradeTs - nbbo.ts > maxAgeMs`), so a quote from *after* the trade produced a negative age and sailed through, letting the engine read a print's direction off an NBBO that may already reflect that print. Nothing exercised it while every source published the quote carrying its own trade's `ts` — an independent quote feed is what changes that. Same class as measuring an outcome from the first print instead of `decisionAt`.
- **`backend/test/vendorMirror.test.ts` enforces the vendoring obligation** that was previously only described here. It compares `backend/src/flow-engine` against `quantflow-modules/flow-engine/src`, and `backend/src/enrichment/firecrawl` against its module, modulo import-extension stripping. Two divergences are **declared** — `resetDaily()` and the firecrawl vendoring header — written as precise strips rather than per-file exemptions, so nothing else can hide behind them. It found real drift on its first run: two comment edits made in `flow-engine/types.ts` and never mirrored, since fixed. The Polygon trades path fetches its NBBO separately, bounded by `timestamp.lte` at or before the trade's own nanosecond timestamp — asking for the *current* quote would be useless against the 2s window and look-ahead against an older print. The quote is published under **its own** timestamp via `RawPrint.quoteTs`, not the trade's, because stamping a five-second-old quote as simultaneous manufactures the freshness the staleness rule exists to judge. Lookups are deduped per contract and capped at `POLYGON_QUOTE_BUDGET` per cycle: 25 trades a poll against a vendor whose free tier allows five calls a minute. A quote failure sets `sourceNotes.polygon` rather than flipping the source to `error` — plans commonly include trades and not quotes, and a connected-but-non-directional feed is invisible if the only vocabulary is connected/error. **No call has ever been made against real Polygon from this repo; the integration is covered by stubs only.** Chain-snapshot connectors (marketData, schwab, tastytrade, yahoo) synthesize prints from aggregate volume and are flagged `synthetic: true` on the wire.
- `heatScore.ts` / `sweepDetector.ts` are superseded by the flow engine. Four connectors still import them to build their own events, but those values are discarded by the adapter — do not add new callers.
- **The settings page reads `/api/health`; it does not collect keys.** It used to render twenty-one password inputs over a save handler that was `setSaved(true)` and nothing else — you pasted a Tradier token, were shown "✓ KEYS SAVED", and the value was discarded on the next navigation. Implementing that save would not have helped, which is the actual finding: connectors read their credentials **once at module load** into module-level consts, and there is one process-wide ingestion pipeline emitting one global `flow_batch`, so there is no per-user key path to write into. `supabase/schema.sql` has an `api_keys` table (RLS policies, index, trigger) that nothing reads or writes and that cannot work without making ingestion per-user; its plaintext `key_value` is documented as such rather than dropped, because that file is run by hand and what is deployed cannot be verified from the repo. Every status on the page now derives from `sources` / `sourceErrors` / `rightsRefusals`, which retired three hand-maintained lists that had each been corrected twice as sources changed state — and were wrong in between. The page also listed Alpaca and Alpha Vantage keys, and `CBOE_ENABLED`, none of which exist in the backend.
- **Every connector that reports `disabled` names the variable that would enable it.** `startConnector` did this for the thirteen from `CONNECTOR_CREDENTIALS`; Tradier, Polygon and Finnhub start on their own paths and set `sources[x] = 'disabled'` with no reason, so `/api/health` reported three sources as off while naming nothing actionable. `markNoCredentials()` is the shared path, and `connectorCredentials.test.ts` fails on a bare `sources[...] = 'disabled'` assignment.
- **The Socket.IO feed is gated at the handshake, on the same terms as `/api/flow`.** It was the one door with no lock: every REST route sits behind `requireAuth` or `requireAuthOrDemo`, and `/api/flow` serves exactly the signals the socket broadcasts — but `io.on('connection')` admitted anyone who connected, with `cors.origin: '*'` and `credentials: true`, so any page on any origin could open a socket and receive `flow_batch` in real time. `authenticateSocket()` lives in `middleware/auth.ts` beside the middleware it mirrors so the two tiers cannot drift, and `io.use()` applies it during the handshake rather than after the connection is established. Same two independent conditions as the HTTP tier: a demo socket needs `DEMO_MODE=1` **and** the client to ask. The refusal reason is deliberately just `Unauthorized` — it crosses to an unauthenticated caller and must not say which condition failed. Socket CORS is now `CORS_ORIGINS`; unlike the HTTP path (which arrives via the frontend's server-to-server rewrite and sends no `Origin`), `NEXT_PUBLIC_WS_URL` points the browser straight at the backend, so origin genuinely matters there.
- **`frontend/lib/socket.ts` passes `auth` as a callback, not an object, and that is load-bearing.** socket.io re-invokes it before every connection attempt, so a reconnect picks up the current Supabase access token. A plain object would freeze whatever token existed when the module-level singleton was built; tokens are short-lived, so the socket would work until the first network blip and then fail its handshake with an expired token. A page reload always looks fine, which is what makes that failure easy to ship. `onAuthStateChange` also reconnects on sign-in/out/refresh, because the server does not re-evaluate an established socket's identity.
- **A refused feed and a down backend look identical in the UI.** `useFlowFeed` substitutes simulated prints for both, so the terminal keeps rendering and does not look broken. That is why `server.ts` warns at boot when neither a Supabase client nor `DEMO_MODE=1` exists — every socket will be refused, and nothing on screen will say so.
- Simulation/fallback mode means the app is fully functional without any live market-data API keys configured; don't assume missing keys are a bug when testing locally.
- `sourceErrors` in `/api/health` is served **unauthenticated**, so every string that reaches it is public. `src/ingestion/httpError.ts` is the one place that formats a vendor failure for it: it carries the vendor's own response body through (a hardcoded guess about *why* a source is down is how that route ended up confidently wrong) and scrubs anything credential-shaped on the way out. Use `describeHttpError` for new connector failures rather than hand-rolling a string, and keep connector keys in headers rather than query strings.
- Enrichment responses carry `context_only: true` and a `disclaimer` field. That is an honesty contract of the same kind as `synthetic` and `side: AMBIGUOUS` — Firecrawl news is a context layer and must never be presented as a trade trigger. Keep it on the payload; a comment does not reach an API client.
- The enrichment routes are registered **above** `/:symbol` in `routes/sentiment.ts`. That route matches any single path segment, so a single-segment route declared after it is captured as a ticker symbol.
- `/api/sentiment/regulatory/:slug` resolves against a server-side allowlist rather than accepting a `?url=`. A caller-supplied URL would make an authenticated endpoint into a request forwarder billed to this account — SSRF and credit drain in one. Adding a source is a code change.
